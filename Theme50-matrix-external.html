Theme #50 Contribution Matrix (draft)

Turns the idea of "coverage + evidence + independent witness" into a submission framework that can be mapped onto the seven deliverables of Theme #50. This document is a proposal draft; it was published in this repository on 2026-10-30 together with the consolidated proposal, and posted to the Theme #50 issue thread (comment 6518762419).

1. What Theme #50 is (verified against primary sources · 2026-10-30)

Theme #50 = Completeness and Coordination of FG-TIDA Pre-standardization Activities, raised by Rémy F. (IN Groupe) on 2026-10-22, currently open, 10 comments (as of 2026-10-29). Primary source: FG-TIDA/themes · Issue #50. Its objective is to take stock of, and coordinate, pre-standardization activity, organised around seven standardisation-need themes (terminology / identity / authority / policy / runtime / evidence / governance). The issue lists seven deliverables:

  1. Standardisation Needs Framework (seven-theme structure)
  2. FG-TIDA Coverage and Maturity Map (with an optional machine-readable format)
  3. External Standards Landscape (cross-checking gaps, overlaps and terminology drift)
  4. Overlap, Dependency and Coordination Matrix
  5. Gap Analysis
  6. Recommendations (contributions, liaison priorities, sequencing)
  7. External Completeness Narrative (including boundaries and dependencies)

VerifiedThe seven items above are reconstructed item by item from the Objectives/Deliverables section of the issue text. Note also that Open Question 2 of #50 itself proposes the four-way outcome "fully / partly / externally / not covered" and asks for the criteria by which it should be judged — which is precisely where this matrix lands. An earlier version said "six tasks" and "current first priority"; neither matched the source text and both have been corrected.

2. Contributions already submitted by Xinghua Zhao (zhaoxinghua09-cell, independent expert) that received a response (locatable verbatim)

Primary source: Issue #50 comment thread (one comment on 10-27, three on 10-29); the originator Remy responded on 10-28, adopting the suggestion and updating both the issue title and body. Scope of adoption, please note: what Remy has explicitly adopted is the machine-readable index suggestion of 10-27 (see the 10-28 reply). On the three points raised on 10-29 — the evidence column, the M0–M4 ladder, and the universe-difference — Hernán has responded in acknowledgement, but Remy has not yet responded. An external submission must therefore not state in general terms that all of it "has been adopted".

  1. Machine-readable index as a starting point (10-27): produce a theme→work-item index from the current GitHub state as an early baseline; adopted by Remy on 10-28 ("A first index … could provide an early baseline").
  2. Keep the four-way outcome un-collapsed (10-29, in response to Open Question 2): the four categories (fully / partly / externally / not covered) are proposed in the #50 text itself; the contributor's contribution is the argument that "externally covered" must not be folded into the other three — that is the precondition for this matrix to exist at all.
  3. An orthogonal evidence column (10-29): the four-way outcome says only where coverage lies, so a further column is needed to record "what supports that label" (stated / specified / enforced / observed); otherwise a row that has merely been declared reads the same as a row that has actually been observed.
  4. The M0–M4 witness-maturity ladder (10-29): each level is defined by "who, other than the author, can confirm it", ordered by witness rather than by mechanism — mechanisms (credentials, runtime attestation) answer different questions and do not form a single ranking (raised by Hernán, explicitly agreed by Xinghua Zhao on 10-29 at 16:01).
  5. Record the universe difference in both directions (10-29): the map must record the universe it was drawn from and the difference in both directions — "declared but outside the universe" and "inside the universe but undeclared"; otherwise "no gap found" and "no gap looked for" read the same in the table.
  6. Negative control case (10-29): the mirror image of Hernán's negative case (a declaration that is schema-valid but unverified) is the row that is marked covered merely because someone posted a proposal; in both cases a self-declaration occupies a position that should have been examined.

Two hotspots (revised per Muse S6 review): (1) the not-covered column is the coverage gap — there is no evidence of any kind for that theme; (2) the covered-but-unwitnessed diagonal cells (fully × author self-statement, partly × specification) are evidence gaps — this is where "format completeness ≠ technical completeness" lands: it looks complete, yet was never run and never independently witnessed. The most dangerous cell is author self-statement × not covered: claimed but absent — false coverage is more dangerous than silence. Note also that independent witness × externally covered = transferable (external), a first-class transfer candidate of the same standing as fully × independent witness. Rows are ordered by witness, not by mechanism — a credential and a runtime attestation answer different questions and do not substitute for one another (consistent with Hernán's 10-29 correction and the agreement confirmed in the thread at 16:01).

4. How the matrix maps onto the seven #50 deliverables

  • Deliverable 1, needs framework: the columns of the matrix are the evidence dimensions and can be expanded theme by theme across the seven themes.
  • Deliverable 2, coverage and maturity map: carried directly by this matrix (four-way outcome + witness axis + two hotspots); the machine-readable format can be produced as CSV/JSON from the same data.
  • Deliverable 3, external standards landscape: this matrix can supply input to that deliverable, and the crosswalk can serve as a supporting tool for mapping standard → design property. The matrix cannot assign that task; the submitter is only offering a capability.
  • Deliverable 4, overlap and dependency matrix: likewise, the LGD ecosystem interlink register can support the avoidance of duplicated work; it is not assigned by this matrix.
  • Deliverable 5, gap analysis: the two hotspots are the primary gap output, and the "universe difference recorded in both directions" guarantees that a gap is "not found" rather than "not looked for".
  • Deliverable 6, recommendations: this submission proposes using "evidence catalogue + independent witness" as the threshold for subsequent hand-over to an SDO; this is the submitter's proposal, not an inherent property of the matrix.
  • Deliverable 7, completeness narrative: can cite this matrix together with the negative control case to write "how we know the coverage is real".
